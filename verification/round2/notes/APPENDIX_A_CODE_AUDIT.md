두 프로그램은 생성기(수준열과 WROM)와 점화식의 구현 형태(순차 병합과 곱)가 다르다.
여기에 생성 방식이 또 다른 제3 프로그램(중심 뿌리 다중집합)과, 나무마다 만든 AHU
표준형 코드의 중복 검사를 더했다([COMPLETENESS_PROOF.md](COMPLETENESS_PROOF.md)).

## 정수 자료형의 폭

| 항목 | Program I | Program II | 제3 프로그램 |
|---|---|---|---|
| 계수 | 64비트 무부호 정수 | 64비트 무부호 정수 | 64비트 무부호 정수 |
| 로그오목 판정의 곱 | 128비트 정수 (199–200행) | 128비트 정수 (154–156행) | 128비트 정수 |
| 나무 수 점화식 | 128비트로 누적 | 128비트로 누적 | 128비트로 누적 |
| 평균 점프 부등식 판정 | 128비트 정수 (214–217행) | 해당 없음 | 128비트 정수 |

넘침이 없다는 근거는 다음과 같다. 어느 중간 상태든 크기 m≤27인 부분나무의 부분집합을
한 번씩만 분류하므로, 한 상태의 k차 계수는 C(m,k) 이하이고 2^27보다 작다. 곱셈의
중간 결과도 서로소인 부분나무들의 부분집합 선택을 세므로 같은 상계를 가진다. 따라서
계수는 64비트에 들어가고, 로그오목 판정의 곱은 2^54보다 작아 128비트에서 넘치지
않는다. 위수별 계수 합은 t_27·2^27<2^57이다. 제3 프로그램의 점프 비교에서 분자는
절댓값이 2^59보다 작고 분모는 2^54보다 작아, 교차곱이 부호 있는 128비트 범위 안에
있다. r_n과 t_n은 임의 정밀도 산술로 다시 계산해 표 1과 대조했다
([../checks/TABLE_COUNTS.json](../checks/TABLE_COUNTS.json)).

## 참고: 부동소수점이 쓰이는 한 곳

원고 937–940행은 "All arithmetic is exact integer arithmetic; no floating-point
comparison enters any of the reported checks."라고 적는다. 정리의 성립 여부를 가르는
검사(로그오목, 단봉, 평균 점프 부등식)는 모두 정수 산술이다. 다만 Program I이
출력하는 통계값 max_mean_jump(218–220행)는 double로 계산한다. 이 값은 7절의
"1.04보다 작다"는 서술에 쓰이는데, 제3 프로그램이 정확한 유리수로 구한 최댓값이
73094/70925≈1.03058이어서 서술은 그대로 성립한다
([../checks/SEC7_JUMP_CENSUS.json](../checks/SEC7_JUMP_CENSUS.json)).
